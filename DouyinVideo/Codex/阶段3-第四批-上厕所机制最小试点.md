# 阶段 3 第四批：上厕所机制最小试点

日期：2026-06-16  
目标：在不改现有核心系统、不改场景和 Prefab 绑定的前提下，新增一个默认关闭的娱乐机制最小代码试点。

## 当前结论

本批新增运行时代码，但不会自动参与当前 `VideoScene`。

原因：

1. 新脚本没有挂到现有场景或 Prefab 上。
2. `ToiletMechanismManager` 的启用开关默认是 `false`。
3. 没有修改 `BaseRole`、`VideoGameManager`、武器、能量球、胜负逻辑。
4. 没有新增 `GameModeManager` 或 `GameMode` 枚举。

这批的意义是：先把“娱乐机制应该独立接入”的代码形态跑通，避免以后继续把机制字段塞进 `BaseRole`。

## 脚本职责

| 脚本 | 职责 | 不负责 |
|---|---|---|
| `ToiletMechanismManager` | 机制开关、便意增长、满值扣血、进入厕所后的停留调度 | 不生成随机厕所，不接管游戏流程，不判断胜负 |
| `RoleToiletState` | 保存单个角色便意、是否正在厕所、调用 `BaseRole` 公开接口 | 不查找所有角色，不生成场景对象 |
| `ToiletArea` | 检测角色进入厕所触发器，并通知 Manager | 不保存机制规则，不直接扣血 |

## Inspector 默认值

| 字段 | 默认值 | 说明 |
|---|---|---|
| `enableToiletMechanism` | `false` | 默认关闭，保护正常模式 |
| `showDebugLog` | `false` | 默认不刷日志 |
| `urgeIncreaseInterval` | `2f` | 便意增长间隔 |
| `urgeIncreaseValue` | `5` | 每次增长便意值 |
| `maxUrge` | `100` | 便意最大值 |
| `damageInterval` | `1f` | 满值后扣血间隔 |
| `damagePerTick` | `5` | 每次扣血 |
| `broadcastDamageNews` | `false` | 满值扣血默认不播报，避免刷屏 |
| `stayDuration` | `5f` | 进入厕所后的强制停留时间 |
| `broadcastEnterNews` | `true` | 进入厕所默认播报 |

## 数据流

```text
ToiletMechanismManager.enableToiletMechanism
→ 遍历 VideoGameManager.instance.circleRoles
→ 运行时为角色挂接 RoleToiletState
→ RoleToiletState 记录便意
→ 便意满值后调用 BaseRole.TakeDamage
→ ToiletArea 检测角色进入厕所
→ RoleToiletState 调用 BaseRole.SetSpeed(0, stayDuration)
→ 停留结束后便意清零
```

## 如何使用

当前这批不会自动生效。  
如果你以后想手动试跑：

1. 在场景中新增一个空物体，挂 `ToiletMechanismManager`。
2. 勾选 `enableToiletMechanism`。
3. 新增一个厕所区域物体，给它加 `Collider2D`，并勾选 `Is Trigger`。
4. 在厕所区域物体上挂 `ToiletArea`。
5. 将 `ToiletMechanismManager` 拖到 `ToiletArea` 的 `mechanismManager` 字段。
6. 运行 `VideoScene` 后，角色进入厕所触发器才会触发停留和清空便意。

注意：  
本批没有实现厕所随机生成，也没有新增厕所 Prefab。  
如果场景里没有手动放 `ToiletArea`，即使 Manager 开启，也只会出现便意增长和满值扣血，不会有“进入厕所”的效果。

## 本批刻意不做

1. 不实现随机厕所生成。
2. 不新增厕所 Prefab。
3. 不新增 UI。
4. 不新增音效。
5. 不新增 `GameModeManager`。
6. 不新增 `GameMode` 枚举。
7. 不修改 `BaseRole` 里的历史遗留 `lashiValue` 字段。
8. 不修改 `VideoGameManager` 的启动流程。
9. 不修改武器刷新、能量球生成、胜负条件。

## 风险说明

| 风险点 | 等级 | 说明 |
|---|---|---|
| 新增脚本参与编译 | 中低 | 如果脚本写错会影响编译，但不会自动改变玩法 |
| 手动启用机制后会改变玩法 | 中 | 这是娱乐机制预期效果，默认关闭 |
| 使用 `BaseRole.TakeDamage` 和 `SetSpeed` | 中 | 手动启用后会调用现有公开接口，需要重点验证 |
| 未绑定场景 | 低 | 当前正常模式不会自动运行本机制 |

## 建议验证

| 验证项 | 说明 |
|---|---|
| 默认运行 `VideoScene` | 确认正常模式表现不变 |
| Unity 编译 | 确认新增脚本无编译错误 |
| 手动挂 Manager 但不勾选开关 | 确认机制不生效 |
| 手动勾选开关且不放厕所区域 | 确认只会便意增长和满值扣血 |
| 手动放厕所区域 | 确认角色进入后停留约 5 秒，结束后便意清零 |
| 游戏结束后 | 确认机制循环停止 |

1. 删除 `Assets/Scripts/Entertainment/` 及 `Assets/Scripts/Entertainment.meta`。
2. 从 `Assembly-CSharp.csproj` 删除三条 `Assets\Scripts\Entertainment\...` 编译引用。

如果你已经手动把 Manager 或 Area 挂进场景，需要先从场景中移除这些组件，再删除脚本。
