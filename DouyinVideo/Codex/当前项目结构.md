# 当前项目结构

创建日期：2026-06-16  
审查方式：静态代码阅读  
主场景：`Assets/Scenes/VideoScene.unity`

## 项目定位

这是一个用于录制短视频素材的 Unity 自动乱斗项目。运行后，角色小球自动运动、碰撞、拾取武器、吃能量球、释放大招，直到剩余最后一名获胜者。

当前不是面向玩家操作的正式游戏，也不需要打包发布。

## 当前模式

当前只有正常模式。

未来可以预留娱乐模式，用于添加观众爱看的奇怪机制，例如上厕所机制、随机场地事件、Buff/Debuff、临时道具等。

## 主入口

当前应以 `VideoScene` 为准。

核心对象：
- `VideoGameManager`：挂在场景中的 `Main Camera` 上。
- `AudioManager`：同样挂在 `Main Camera` 上。
- `circleRoles`：由 `VideoGameManager` 在 Inspector 中绑定当前参战角色。
- `Weapons`：由 `VideoGameManager` 在 Inspector 中绑定可随机刷出的武器。

## 核心玩法流程

1. 场景启动。
2. `VideoGameManager` 初始化角色状态 UI。
3. 每个角色通过 `BaseRole` 获得随机初始力。
4. 角色在场地内自动弹动。
5. 武器和能量球被随机生成。
6. 角色碰到能量球后获得大招点。
7. 角色大招点满后自动释放大招。
8. 角色受到伤害，血量归零后被淘汰。
9. 剩余最后一名角色时，游戏结束并展示胜者。

## 主要脚本职责

| 脚本 | 职责 |
|---|---|
| `VideoGameManager` | 全局流程、角色列表、武器生成、能量球生成、胜负判断、部分 UI 特效 |
| `BaseRole` | 角色基础能力，包括生命、移动速度、大招能量、受伤、死亡、状态限制 |
| `RoleUI` | 角色血量、大招点、头像等 UI 显示 |
| `Broadcast` | 战报文本生成和滚动 |
| `AudioManager` | 背景音乐和音效播放 |
| `RandomChoose` | 随机英雄选择 UI，目前主流程是否使用需要按场景激活状态确认 |
| `Knief` | 小刀拾取、旋转、命中、回收 |
| `BiaoPei` | 标配武器拾取、射击、回收 |
| `AoDing` | 奥丁武器拾取、射击、减速、回收 |
| `VideoGameBulletBase` | 通用子弹移动、命中角色和墙体回调 |

## 英雄脚本特点

所有英雄都继承 `BaseRole`。  
每个英雄的大招差异较大，因此大招逻辑目前适合保留在各自脚本中。

常见重复模式：
- 停止旧大招协程。
- 启动新大招协程。
- 前摇等待。
- 播报技能。
- 选择目标。
- 使用射线、投射物或范围检测。
- 命中后造成伤害或状态。
- 技能结束后回收表现对象。

## 当前主要耦合点

| 耦合点 | 说明 | 后续建议 |
|---|---|---|
| 单例 | `VideoGameManager.instance`、`AudioManager.Instance`、`Broadcast.instance` 被大量直接访问 | 短期保留，长期可通过上下文或服务封装减少直接依赖 |
| 字符串 Tag/Layer | `Role`、`wall`、`BigBall`、`Weapon`、`YeLu` 等字符串散落多处 | 阶段 1 提取常量 |
| 场景层级名 | `Canvas`、`负面效果` 等层级名被代码依赖 | 阶段 1 提取常量并缓存 |
| 英雄技能流程 | 多个英雄脚本重复实现协程管理、播报、命中检测 | 阶段 2 提取基础能力工具 |
| 武器流程 | 多个武器重复实现拾取、挂载、瞄准、射击、回收 | 阶段 5 整理武器系统 |

## 当前不建议立刻修改的点

| 区域 | 原因 |
|---|---|
| 武器刷新规则 | 改动可能影响视频表现节奏 |
| 能量球生成规则 | 改动可能影响大招释放频率 |
| 胜利后表现 | 改动可能影响录制画面 |
| `BaseRole` 继承结构 | 当前所有英雄依赖它，风险较高 |
| Prefab/Scene 绑定 | 改动难以从代码 diff 中直接判断影响 |
