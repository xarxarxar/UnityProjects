# 阶段 6 第三批：音效对象池试点

日期：2026-06-16  
目标：减少录制过程中 SFX 音效反复 `Instantiate` / `Destroy` 带来的对象生命周期开销。  
主场景：`Assets/Scenes/VideoScene.unity`

## 本批结论

本批只改 `AudioManager` 的 SFX 播放路径。

原逻辑：

1. 每次播放 SFX 时实例化 `sfxSourcePrefab`。
2. 设置 `clip`、`volume`、`pitch`。
3. 调用 `Play()`。
4. 在 `clip.length / pitch` 后销毁音效对象。

新逻辑：

1. 每次播放 SFX 时先从池中取一个可用 `AudioSource`。
2. 池为空时，仍按原方式实例化 `sfxSourcePrefab`。
3. 设置 `clip`、`volume`、`pitch`。
4. 调用 `Play()`。
5. 在 `clip.length / pitch` 后停止、清空 `clip`、隐藏对象，并放回池中复用。

没有改动：

- 没有修改任何音效 key。
- 没有修改音效音量数值。
- 没有修改 pitch 默认值。
- 没有修改播放时长公式。
- 没有修改 BGM 逻辑。
- 没有修改 Scene、Prefab、Inspector 绑定。
- 没有修改 `BaseRole` 的吃球、碰撞触发点。

| `Assets/Scripts/Audio/AudioManager.cs` | 为 SFX `AudioSource` 增加运行时对象池，播放结束后回收复用 | 否 | 中低 |

## 关键实现

### `sfxPool`

新增运行时队列：

```csharp
private readonly Queue<AudioSource> sfxPool = new Queue<AudioSource>();
```

作用：

- 存放已经播放结束、隐藏起来的 SFX `AudioSource`。
- 不暴露到 Inspector。
- 不预创建对象，避免改变场景启动状态。

### `GetSfxSource()`

作用：

- 如果池中有可用对象，就取出并激活。
- 如果池为空，就继续用原来的 `Instantiate(sfxSourcePrefab, transform)`。

这样可以保持第一次并发音效的创建行为基本不变，只减少后续重复播放时的销毁和重建。

### `ReturnSfxSourceAfterPlaying(...)`

作用：

- 等待 `clip.length / pitch`。
- 停止音效。
- 清空 `clip`。
- 隐藏对象。
- 放回池中。

这里保留了原来的播放时长公式：

```csharp
clip.length / pitch
```

## 风险说明

本批风险为中低。

原因：

- 从“延迟销毁对象”改成“协程等待后回收对象”，音效对象的生命周期实现方式发生变化。
- 这不会改变玩法规则，但可能影响音效对象在 Hierarchy 中的可见状态。
- 如果未来有外部代码引用这些临时 SFX 对象并期待它们被销毁，则需要重新评估；当前代码搜索未发现这种引用。

已控制的风险：

- `PlaySFX(string key)` 和 `PlaySFX(string key, float pitch)` 调用方式不变。
- `BaseRole` 调用点不变。
- `sfxSourcePrefab` 绑定不变。
- 音效播放参数仍在每次播放前重新设置。
- 回收时清空 `clip`，避免重新激活时受到上一段音效影响。
