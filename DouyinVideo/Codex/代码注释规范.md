# 代码注释规范

本规范用于后续维护 Unity 脚本时保持代码易读，但不过度注释。

## 总原则

1. 注释使用中文。
2. 注释解释“用途”和“注意事项”，不要逐行解释语法。
3. 公开方法必须优先使用 XML 注释。
4. 重要私有方法使用 XML 注释。
5. 普通私有小方法如果一眼能看懂，可以不写 XML 注释。
6. 复杂脚本可以使用 `#region` 和 `#endregion` 整理结构。
7. 不为了分区而分区，小脚本保持简洁。

## 字段注释

Inspector 可见字段优先使用 `[Tooltip("说明")]`。

示例：

```csharp
[Tooltip("角色初始血量")]
public int HP = 100;
```

如果字段不会出现在 Inspector，可以使用普通注释或不注释。

## 方法注释

公开方法建议使用：

```csharp
/// <summary>
/// 设置角色移动速度倍率。
/// </summary>
/// <param name="percent">速度倍率，1 表示正常速度。</param>
/// <param name="duration">持续时间，0 表示永久生效直到下次修改。</param>
public void SetSpeed(float percent, float duration = 0)
{
}
```

有返回值时写：

```csharp
/// <summary>
/// 获取除自身外的随机存活角色。
/// </summary>
/// <param name="self">当前角色。</param>
/// <returns>随机目标；如果没有可选目标则返回 null。</returns>
public BaseRole GetRandomOther(BaseRole self)
{
}
```

## 私有方法注释

重要私有方法写 XML 注释。  
例如复杂协程、命中检测、状态恢复、生成流程。

普通小工具方法可以不写，避免脚本太杂乱。

## 分区规范

复杂脚本可使用中文 `#region`。

推荐命名：

```csharp
#region 字段配置
#endregion

#region Unity生命周期
#endregion

#region 大招逻辑
#endregion

#region 状态处理
#endregion

#region 开发调试入口
#endregion

#region 工具方法
#endregion
```

注意：
- 不要求每个脚本都有这些分区。
- 一个脚本少于约 50 行时通常不需要分区。
- 分区是为了阅读，不是为了形式。

## 调试入口注释

调试按键可以保留，但必须集中或标注。

```csharp
#region 开发调试入口

private void Update()
{
    if (Input.GetKeyDown(KeyCode.M))
    {
        UseBig();
    }
}

#endregion
```

## 不推荐的注释

不推荐：

```csharp
// i 加 1
i++;
```

推荐：

```csharp
// 按路径顺序回拉目标，保持钢索折线路径表现。
```

## 机制注释

新增玩法机制时，应在类注释中说明：
- 这是正常机制还是娱乐机制。
- 是否默认启用。
- 依赖哪些对象或系统。

示例：

```csharp
/// <summary>
/// 娱乐模式机制：记录角色便意，并在便意过高时触发扣血。
/// </summary>
public class RoleToiletState : MonoBehaviour
{
}
```
