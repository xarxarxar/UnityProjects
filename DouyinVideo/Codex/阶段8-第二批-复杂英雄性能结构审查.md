## 本批结论

本批只做审查和决策，不修改游戏代码。

结论：

- 阶段 8 第三批建议优先处理 `FireWallFireManRole.cs`。
- `GangsuoRole.cs` 暂不作为第一轮代码试点，因为它直接移动目标角色、禁用碰撞体、改 `canUseBig`，玩法风险更高。

- `DiJiaRole.cs` 结构较短，性能问题相对集中，后续可以单独小批次整理。

## 为什么优先火墙火男

`FireWallFireManRole` 有明确性能优化价值，但玩法耦合没有钢索那么危险。

代码证据：

| 位置 | 说明 | 判断 |
|---|---|---|
| `FireWallFireManRole.cs:29` | 存在开发调试 `Update()`，按 `O` 键释放大招并回血 | 可整理，但需保持调试行为 |
| `FireWallFireManRole.cs:38` | `DrawFireWall()` 控制完整大招流程 | 函数较长，适合拆私有方法 |
| `FireWallFireManRole.cs:58` | 启动 `PlayFlameLoop()` 火焰帧动画协程 | 可加边界保护，避免空数组或非法帧率 |
| `FireWallFireManRole.cs:89` | 5 秒内每帧 `Physics2D.RaycastAll(...)` | 性能热点，但不能直接改 `NonAlloc`，命中顺序风险未知 |
| `FireWallFireManRole.cs:120` | 命中同一目标后按 `0.15f` 间隔造成 3 点伤害 | 玩法数值和节奏不可改 |
| `FireWallFireManRole.cs:121` | 每次伤害都播报一次战报 | 可能造成大量 UI 文本，但改播报频率会改变观感，暂缓 |
| `FireWallFireManRole.cs:152` | 协程内 `StopCoroutine(fireCoro)` 后再置空 | 可审查是否改为直接置空，但需谨慎 |
| `FireWallFireManRole.cs:158` | `PlayFlameLoop()` 使用 `WaitForSeconds(waitTime)` | 可缓存 `waitTime` 相关逻辑，但不改帧率 |
| `FireWallFireManRole.cs:171` | `RecoverHealth()` 只允许触发一次 | `isRecovered` 行为不能改 |

## 火墙火男当前流程

```text
Big()
-> 开启 lineRenderer 对象，重置 isRecovered
-> 停止旧 fireCoro
-> StartCoroutine(DrawFireWall())

DrawFireWall()
-> 等待 1 秒
-> 取自身位置和随机目标方向
-> 0.5 秒延伸火墙
-> 启动 PlayFlameLoop()
-> 5 秒内每帧 RaycastAll 检测命中
   -> 命中自己：尝试 RecoverHealth()
   -> 命中其它角色：同一目标每 0.15 秒扣 3 点血并播报
-> 关闭 lineRenderer 和火焰帧循环
```

## 下一批允许的安全优化

阶段 8 第三批如果处理 `FireWallFireManRole.cs`，建议只做以下低风险内容：

| 允许项 | 原因 | 风险 |
|---|---|---|
| 添加中文 region 和重要方法 XML 注释 | 提升可读性，不改逻辑 | 低 |
| 抽出 `StopFireCoroutine()`、`StopFlameLoop()`、`StartFlameLoop()` 这类私有方法 | 减少重复 `StopCoroutine + null` | 低 |
| 抽出 `ResetFireWallState()`、`CloseFireWall()` | 收口 `lineRenderer` 和 `isRecovered` 状态 | 中低 |
| 抽出 `TryStartRecoverHealth()` | 保持原来命中自己时启动回血协程的顺序 | 中低 |
| 缓存 `LayerMask.GetMask("YeLu")` 结果 | 避免每次大招重复计算，不改变命中规则 | 低 |
| 给 `frameRate <= 0`、`flameFrames` 空数组增加保护 | 防止配置错误导致除零或取模异常 | 中低 |
| 删除或标注调试 `Update()` | 如果保留行为，只加注释；若删除需要单独确认 | 低到中 |

## 下一批暂时不要做

| 暂缓项 | 原因 |
|---|---|
| 不把 `RaycastAll` 改成 `RaycastNonAlloc` | `RaycastAll` 命中顺序和数组分配语义会影响“第一个角色”判断 |
| 不改变 `damageInterval = 0.15f` | 直接影响伤害频率和战报节奏 |
| 不改变 `maxDuration = 5.0f` | 直接影响大招持续时间 |
| 不减少每次伤害战报 | 会改变视频观感和信息密度 |
| 不改变 `RecoverHealth()` 的回血次数、间隔、数值 | 直接影响生存能力 |
| 不调整火墙长度 `20`、延伸时间 `0.5f`、等待时间 `1.0f` | 都是玩法表现参数 |
| 不同时处理钢索、绊线保安、迪迦 | 避免跨英雄批量改动导致问题难定位 |

## 其它候选暂缓原因

### 钢索

`GangsuoRole.cs` 暂缓作为第一轮代码试点。

原因：

- `GangsuoRole.cs:47` 直接写 `canUseBig = false`。
- `GangsuoRole.cs:80` 让目标 `SetSpeed(0)`。
- `GangsuoRole.cs:81` 禁用目标 `Collider2D`。
- `GangsuoRole.cs:170` 每帧直接改目标 `transform.position`。
- `GangsuoRole.cs:155` 结束时造成 50 点伤害。

这些都是玩法核心链路，不适合作为阶段 8 第三批的第一刀。

### 绊线保安

`BanXianBaoAnRole.cs` 有持续 `RaycastAll`，但发射器、接收器、激光线和命中后折线表现绑得很紧。

下一步可以审查，但建议排在火墙之后。

### 迪迦

`DiJiaRole.cs` 逻辑较短，主要问题集中在激光协程、每帧射线和 `LayerMask.GetMask()`。

它适合后续做小批次清理，不需要抢在火墙前面。
