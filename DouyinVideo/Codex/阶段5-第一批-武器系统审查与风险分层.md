# 阶段 5 第一批：武器系统审查与风险分层

日期：2026-06-16  
目标：在不修改游戏代码的前提下，梳理当前武器系统从刷新、拾取、挂载、攻击、命中到回收的完整链路，并明确后续安全整理边界。

## 本批范围

本批只做审查和文档整理。

没有改动：

1. 游戏代码。
2. Prefab、Scene、Inspector 绑定。
3. 武器刷新规则。
4. 武器数值。
5. 子弹命中逻辑。
6. 角色拾取逻辑。
7. `BaseRole`、`VideoGameManager`、英雄脚本。

这些对象看起来像武器或投射物，但当前更像英雄技能生成物，不建议和可刷新武器一起重构：

| 脚本 | 当前判断 | 原因 |
|---|---|---|
| `Hat.cs` | 英雄技能生成物 | 由丢帽子保安、狂鼠等英雄大招驱动，不走 `VideoGameManager.Weapons` 刷新列表 |

| 英雄 Prefab 内置子弹 | 英雄技能表现 | 由各英雄脚本直接驱动，归英雄阶段或技能阶段处理 |

## 当前运行流程

### 1. 武器刷新

代码入口：`VideoGameManager.Start()`。

```text
Start()
→ Invoke(nameof(SpawnWeapons), 3)
→ SpawnWeapons()
→ StartCoroutine(SpawnWeaponsCoroutine())
→ Random.Range(0, Weapons.Count)
→ currentReward = Weapons[index]
→ 如果 currentReward.activeSelf，直接 yield break
→ 随机位置 Random.Range(-9f,13f), Random.Range(-13f,13.5f)
→ currentReward.transform.SetParent(null)
→ currentReward.transform.position = randomPos
→ currentReward.SetActive(false)
→ 等待 Random.Range(1.0f, 2.0f)
→ currentReward.SetActive(true)
```

高风险点：  
这里的 `activeSelf`、随机延迟、随机位置、`SetParent(null)` 都会影响录制画面节奏。阶段 5 后续不要先改。

### 2. 标配 / 奥丁拾取

代码入口：`BiaoPei.OnTriggerEnter2D`、`AoDing.OnTriggerEnter2D`。

```text
OnTriggerEnter2D(collision)
→ 如果 !isAttached
→ collision.CompareTag("Role")
→ pickerRole = collision.GetComponent<BaseRole>()
→ pickerRole.canGetWeapon
→ Broadcast 捡到武器
→ AttachToRole(pickerRole, pickerRole.otherBaseRole)
```

强耦合点：

1. 依赖 Tag：`Role`。
2. 依赖 `BaseRole.canGetWeapon`。
3. 依赖 `BaseRole.otherBaseRole` 随机目标。
4. 依赖 `Broadcast.instance`。

### 3. 标配 / 奥丁挂载

代码入口：`AttachToRole`。

共同流程：

```text
gameObject.layer = LayerMask.NameToLayer("Weapon")
isAttached = true
role = baseRole
targetRole = target
transform.parent.position = role.transform.position
transform.parent.SetParent(role.transform)
currentCount = bulletCount
StartCoroutine(Shoot())
```

奥丁额外流程：

```text
role.SetSpeed(0.2f)
```

高风险点：

1. 武器脚本依赖 `transform.parent` 是武器根物体。
2. 子弹脚本也依赖 `bullet.transform.parent` 是子弹根物体。
3. 奥丁需要在 `SetDeafult()` 里恢复 `role.SetSpeed(1.0f)`。
4. 改父子关系或 Prefab 层级会直接影响运行。

### 4. 标配 / 奥丁射击

标配：

| 项 | 当前值 |
|---|---|
| 子弹数 | `4` |
| 射击间隔 | `1` 秒 |
| 子弹速度 | `50` |
| 命中伤害 | `5` |
| 收尾等待 | `0.5f` |

奥丁：

| 项 | 当前值 |
|---|---|
| 子弹数 | `15` |
| 射击间隔 | `0.17f` |
| 子弹速度 | `70` |
| 命中伤害 | `5` |
| 收尾等待 | `0.5f` |

共同流程：

```text
while(currentCount > 0)
→ 等待射击间隔
→ 设置武器缩放
→ 播放开枪音效
→ 读取 role.transform.position
→ 读取 targetRole.transform.position
→ VideoGameAimUtility.AimZAxisAtTarget
→ VideoGameAimUtility.GetVerticalFlipScale
→ VideoGameAimUtility.GetDirection
→ bullet.Init(...)
→ 设置 bullet.OnBulletHitRole
→ currentCount--
→ 循环结束后等待 0.5f
→ SetDeafult()
→ VideoGameManager.instance.SpawnWeapons()
```

注意：  
两把枪存在明显重复逻辑，但重复逻辑里夹着数值和奥丁减速差异。后续适合小步抽工具，不适合直接引入父类。

### 5. 标配 / 奥丁回收

代码入口：`SetDeafult()`。

共同流程：

```text
gameObject.layer = LayerMask.NameToLayer("Default")
transform.localScale = 原始缩放
transform.parent.gameObject.SetActive(false)
transform.parent.localEulerAngles = Vector3.zero
currentCount = bulletCount
bullet.transform.parent.gameObject.SetActive(false)
isAttached = false
```

奥丁额外流程：

```text
role.SetSpeed(1.0f)
```

注意：  
方法名当前拼写为 `SetDeafult`。后续可以考虑改为 `SetDefault`，但这是跨调用点命名修改，必须单独小步做。

### 6. 小刀流程

代码入口：`Knief.OnTriggerEnter2D`、`Knief.Update`、`DestroyThis()`。

拾取流程：

```text
如果 !isAttached
→ collision.CompareTag("Role")
→ role.canGetWeapon
→ AttachToBall(collision.transform)
```

挂载流程：

```text
gameObject.layer = "Weapon"
ball = ballTransform
isAttached = true
knifeRoot.position = ball.position
knifeRoot.SetParent(ball)
StartCoroutine(DestroyThis())
```

旋转流程：

```text
Update()
→ 如果 gameEnd，gameObject.SetActive(false)
→ 如果 isAttached && ball != null
→ transform.parent.Rotate(... KniefRotateSpeed ...)
```

命中流程：

```text
如果已附着，并碰到其他 Role
→ targetRole.TakeDamage(10)
→ Broadcast 持有者攻击并获得一点能量
→ KniefHoldTime += 1
→ KniefRotateSpeed += 5
→ ownerRole.AddBig()
→ 重置层级、隐藏父物体、复位位置和旋转
→ isAttached = false
→ SpawnWeapons()
```

超时流程：

```text
等待 KniefHoldTime
→ 重置层级、隐藏父物体、复位位置和旋转
→ isAttached = false
→ SpawnWeapons()
→ KniefHoldTime += 1f
→ KniefRotateSpeed += 5
```

高风险点：  
小刀会修改全局 `KniefHoldTime` 和 `KniefRotateSpeed`，并且命中会调用 `ownerRole.AddBig()`。这不是普通枪械流程，后续不应该强行和标配、奥丁抽成一个父类。

### 7. 子弹命中

代码入口：`VideoGameBulletBase.Init`、`VideoGameBulletBase.OnTriggerEnter2D`。

初始化：

```text
direction = dir.normalized
speed = 参数 speed
bulletRoot = transform.parent
bulletRoot.position = startPos
_baseRole = baseRole
tags = tags
bulletRoot.rotation = Quaternion.Euler(0, 0, angle)
bulletRoot.gameObject.SetActive(true)
如果 Rigidbody2D 存在，则 rb.velocity = direction * speed
否则 Debug.LogWarning
```

命中：

```text
如果 collision tag 在忽略 tags 中，return
如果命中 Role 且不是 _baseRole
→ collision.GetComponent<BaseRole>()
→ OnBulletHitRole?.Invoke(role)
否则如果命中 wall
→ OnBulletHitWall?.Invoke()
→ Recycle()
```

回收：

```text
StopAllCoroutines()
transform.parent.gameObject.SetActive(false)
```

注意：

1. 命中 Role 后默认不自动 `Recycle()`，由回调决定。
2. 命中 wall 后一定 `Recycle()`。
3. `tags` 忽略列表目前用于后羿等调用方。
4. `wall` tag 为小写，和部分代码里的注释/文档大小写必须保持一致。

## 强耦合模块

| 耦合点 | 影响 |
|---|---|
| `VideoGameManager.Weapons` 场景绑定 | 改 Prefab 或对象层级可能导致刷新失败 |
| `transform.parent` 作为武器根物体 | 标配、奥丁、小刀都依赖父物体表示整体武器 |
| `bullet.transform.parent` 作为子弹根物体 | 子弹初始化和回收依赖父物体 |
| Tag `Role` / `wall` | 拾取、命中、墙体回收都依赖 Tag |
| Layer `Weapon` / `Default` | 拾取后和回收时直接切换 |
| `BaseRole.canGetWeapon` | 维斯等英雄会影响武器拾取 |
| `BaseRole.otherBaseRole` | 拾取瞬间决定射击目标 |
| `Broadcast.instance` | 拾取和命中播报直接调用 |
| `VideoGameAimUtility` | 标配、奥丁已依赖瞄准工具 |
| `VideoGameCombatUtility` | 标配、奥丁已依赖伤害播报工具 |

## 风险分层

### 低风险，可优先做

| 项 | 说明 |
|---|---|
| 清理无用 `using` | 不改变运行 |
| 增加中文 XML 注释 | 方便后续新增武器 |
| 增加 `[Tooltip]` | 不改字段名和访问级别时较安全 |
| 增加 `#region` | 只影响代码阅读 |
| 文档化武器流程 | 不参与编译 |

### 中风险，需单独验证

| 项 | 说明 |
|---|---|
| 提取 `StopShootCoroutine` 或回收辅助方法 | 必须保持调用顺序 |
| 抽取标配/奥丁共同瞄准逻辑 | 已有工具可用，但不要改缩放数值 |
| 修正 `SetDeafult` 命名 | 会影响调用点，必须小步改 |
| 增加空引用保护 | 可能改变错误暴露方式，需要确认 |
| 子弹回调清理 | 回调保留或清空会影响复用行为 |

### 高风险，暂不建议动

| 项 | 原因 |
|---|---|
| 改 `VideoGameManager.SpawnWeapons` 流程 | 会改变武器出现节奏 |
| 改 `Weapons` 场景绑定 | 不易从代码 diff 看出影响 |
| 改 Prefab 层级 | 当前大量代码依赖 `transform.parent` |
| 改子弹碰撞判断顺序 | 可能改变命中角色/墙体表现 |
| 改 `KniefHoldTime` / `KniefRotateSpeed` 增长 | 直接影响录制节奏 |
| 引入 `BaseWeapon` 并迁移现有武器 | 当前武器数量少，收益暂时不够抵消风险 |
