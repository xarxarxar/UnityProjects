## 现有共性

| 共性 | 代码证据 | 模板决策 |
|---|---|---|
| 英雄统一继承 `BaseRole` | 19 个 `*Role.cs` 都继承 `BaseRole` | 短期继续保留，不新建角色父类 |
| 大招入口统一是 `public override void Big()` | 所有英雄都实现 `Big()` | 新增英雄必须以 `Big()` 为大招入口 |
| 多数英雄用 `Coroutine bigCoro` 控制大招流程 | 奶妈、炸弹妹、钱包、钢索、火墙等 | 模板保留协程引用区 |
| 表现和结算通常放在 `BigCoro()` 或专用协程 | `NaiMaRole.BigCoro`、`QianBaoRole.BigCoro`、`FireWallFireManRole.DrawFireWall` | 推荐入口只负责启动流程 |
| 调试入口散落在 `Update()` | 钱包、钢索、炸弹妹、火墙、猎枭、夜露、狂鼠等 | 必须放到 `#region 开发调试入口` |
| 复杂英雄常直接操作子物体、父子关系、Collider、LineRenderer | 钢索、绊线、烟男、维斯、捷风 | 旧英雄整理必须保守，不先抽公共框架 |

## 新增英雄正式模板

新增英雄可以比旧脚本更规范。模板如下：

```csharp
using System.Collections;
using UnityEngine;

/// <summary>
/// 英雄说明：写清楚英雄定位和大招效果。
/// </summary>
public class XxxRole : BaseRole
{
    #region 字段配置

    [SerializeField, Tooltip("大招前摇时间")]
    private float bigDelay = 1.0f;

    [SerializeField, Tooltip("大招伤害")]
    private int bigDamage = 30;

    #endregion

    #region 协程引用

    private Coroutine bigCoro;

    #endregion

    #region 大招逻辑

    /// <summary>
    /// 释放英雄大招。
    /// </summary>
    public override void Big()
    {
        StopBigCoroutine();
        bigCoro = StartCoroutine(BigCoro());
    }

    /// <summary>
    /// 执行英雄大招流程。
    /// </summary>
    /// <returns>Unity 协程迭代器。</returns>
    private IEnumerator BigCoro()
    {
        yield return new WaitForSeconds(bigDelay);

        BaseRole targetRole = otherBaseRole;
        if (targetRole == null)
        {
            yield break;
        }

        VideoGameCombatUtility.BroadcastThenDamage(
            targetRole,
            bigDamage,
            $"{RoleName}的大招对{targetRole.RoleName}造成了{bigDamage}点伤害",
            roleColor);
    }

    #endregion

    #region 开发调试入口

    private void Update()
    {
        if (Input.GetKeyDown(KeyCode.M))
        {
            UseBig();
        }
    }

    #endregion

    #region 工具方法

    /// <summary>
    /// 停止正在执行的大招协程。
    /// </summary>
    private void StopBigCoroutine()
    {
        if (bigCoro == null)
        {
            return;
        }

        StopCoroutine(bigCoro);
        bigCoro = null;
    }

    #endregion
}
```

## 旧英雄整理模板

旧英雄整理必须保持行为不变，建议只做以下结构调整：

```csharp
public class XxxRole : BaseRole
{
    #region 字段配置
    // 原 public 字段先不改访问级别，避免影响 Inspector 绑定。
    #endregion

    #region 运行状态
    // bool、计数、缓存状态放这里。
    #endregion

    #region 协程引用
    // Coroutine 字段放这里。
    #endregion

    #region 大招入口
    public override void Big()
    {
        // 保持原有调用顺序。
    }
    #endregion

    #region 大招流程
    // BigCoro、持续检测、动画流程。
    #endregion

    #region 命中结算
    // 子弹回调、Raycast 命中、范围检测结算。
    #endregion

    #region 状态复位
    // SetDefault、Recycle、隐藏表现、恢复父节点。
    #endregion

    #region 开发调试入口
    // 现有 Update 调试入口先移动到这里，不改按键。
    #endregion
}
```

注意：  
旧英雄第一轮整理不要同时改字段访问级别、协程顺序、数值、Layer、Tag、父子关系和回调内容。

## 阶段 4 代码整理边界

允许：

1. 移动代码区块但不改变执行顺序。
2. 添加中文 `Tooltip`。
3. 添加 XML 注释。
4. 删除确认未使用的 `using`。
5. 提取只在本脚本内部使用的短工具方法。
6. 给调试入口加 `#region 开发调试入口`。

禁止：

1. 改大招数值。
2. 改 `WaitForSeconds` 时间。
3. 改 `StartCoroutine`、`StopCoroutine` 顺序。
4. 改 `Broadcast` 与 `TakeDamage` 的先后顺序。
5. 改 `SetSpeed`、Layer、Collider、父子关系恢复逻辑。
6. 把多个英雄大招合并成一个父类模板。
7. 现在就整理高风险复杂英雄。
