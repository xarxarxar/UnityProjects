# 安全重构计划

创建日期：2026-06-16  
适用项目：DouyinVideo  
主场景：`Assets/Scenes/VideoScene.unity`

## 当前状态

阶段 0 到阶段 8 已于 2026-06-17 收口，作为一轮完整安全重构计划结束。  
后续如继续推进，建议按“新增英雄专项 / 新增武器专项 / 娱乐机制专项 / 录制稳定性专项”等新目标重新开计划，而不是默认继续追加阶段编号。

收口总结和上手入口见：`Codex/阶段0到8重构收口总结与上手指南.md`。

## 目标

在不改变现有自动乱斗玩法的前提下，逐步提升项目的稳定性、可维护性、可复用性和后续扩展能力。

当前项目的核心用途是录制抖音视频。游戏运行后，角色小球自动弹来弹去、拾取武器、吃能量球、释放大招，直到出现最终获胜者。当前不需要面向玩家操作，也不需要打包发布。

## 总原则

1. 正常模式优先稳定。
2. 所有玩法数值、规则、协程时序、触发顺序默认不改。
3. 不确定是否影响表现的改动，先记录，不直接修改。
4. 所有非游戏运行所需文件放入 `Codex/`。
5. 每次改动都必须记录到 `Codex/修改记录.md`。
6. 代码注释使用中文，重要公开方法使用 XML 注释。
7. 当前所有英雄继续继承 `BaseRole`，短期不改变继承体系。

## 阶段 1：低风险稳定性整理

状态：已完成（2026-06-16）

目标：
- 让现有自动乱斗更稳定。
- 降低空引用、硬编码字符串、重复查找带来的维护风险。
- 不改变玩法表现。

建议内容：
- 提取 Tag、Layer、层级名常量。
- 缓存常用组件，如 `Rigidbody2D`、`Collider2D`、`Canvas`。
- 清理无用 `using`。
- 标注开发调试入口。
- 提取少量函数级重复逻辑。
- 给高风险空引用点加保护。

禁止内容：
- 不改角色数值。
- 不改武器刷新规则。
- 不改能量球刷新规则。
- 不改死亡和胜利表现。
- 不改场景和 Prefab 绑定。

## 阶段 2：基础能力工具化

状态：第四批完成，第三批暂缓（2026-06-16，已抽出武器瞄准、随机目标选择、战斗结果处理工具，并整理新增英雄/武器模板）

- 保留每个英雄大招的独特实现。
- 把通用基础能力抽成可复用工具，降低新增英雄难度。

可抽能力：
- 目标选择。
- 伤害与治疗。
- 速度控制。
- 状态效果。
- 战报播报。
- LineRenderer 辅助。
- 武器瞄准。
- 子弹命中。

原则：
- 不强行把所有大招做成同一个模板。
- 大招仍然允许每个英雄单独写。
- 工具类只服务重复基础能力。

## 阶段 3：正常模式保护与娱乐模式预留

状态：第四批完成（2026-06-16，已新增模式边界设计、机制配置规范、娱乐机制最小入口设计文档，并加入默认关闭的上厕所机制最小试点脚本）

目标：
- 当前项目保持正常模式。
- 为未来娱乐模式预留设计位置。

当前状态：
- 现在只有正常模式。
- 娱乐模式暂不实现。
- 娱乐模式未来可以在正常模式基础上追加奇怪机制。
- 阶段 3 第一批只完成设计文档，不新增 `GameModeManager` 或 `GameMode` 枚举。
- 阶段 3 第二批只完成配置规范文档，不新增运行时配置系统。
- 阶段 3 第三批只完成最小入口设计文档，不指定或实现具体娱乐机制。
- 阶段 3 第四批新增上厕所机制最小试点脚本，但没有挂入场景，默认关闭，不影响当前正常模式。

设计原则：
- 正常模式默认不受娱乐机制影响。
- 娱乐机制不塞进 `BaseRole`。
- 娱乐机制尽量独立成组件或 Manager。
- Inspector 只暴露少量必要配置，避免每次手动配置过多。
- 娱乐机制默认关闭，避免污染正常模式。

## 阶段 6：性能与录制稳定性

状态：第五批完成（2026-06-16，已完成 `flyLightPrefab` 与 `bigBallPrefab` 池化审查，暂未修改游戏代码）

目标：
- 降低长时间录制过程中的卡顿和 GC。

候选项：
- 音效对象池。
- 战报对象池。
- 子弹对象池。
- 特效对象池。
- Raycast 分配优化。
- 减少每帧临时对象。
- 胜利后可选停止无用循环。

注意：
- 性能优化可能改变表现节奏，必须小步进行。
- `RaycastAll` 替换为 `NonAlloc` 时必须确认命中顺序不变。

当前建议：
- 阶段 6 第二批已完成低风险日志、空 `Update`、局部缓存整理。
- 阶段 6 第三批已完成 `AudioManager` 的 SFX 对象池试点，减少吃球和碰撞音效反复创建/销毁。

- 暂不改 `BaseRole.FixedUpdate`，暂不全局替换 `RaycastAll`。
