# 阶段 2 第二批：战斗结果工具化

日期：2026-06-16  
目标：在不改变玩法表现的前提下，把常见的战报、伤害、状态处理抽成轻量工具方法，并减少局部重复 `GetComponent<BaseRole>()`。

## 本批范围

本批只处理以下内容：

1. 新增战斗结果工具类 `VideoGameCombatUtility`。
2. 迁移少量固定顺序的“播报/伤害/状态”代码。
3. 对源氏大刀、维斯、绊线保安等局部命中点缓存 `BaseRole`。

没有改动：

1. 伤害数值。
2. 状态持续时间。
3. 播报文本内容。
4. 大招协程等待时间。
5. 武器/技能回收规则。
6. Prefab、Scene、Inspector 绑定。

## 新增工具说明

### `VideoGameCombatUtility`

用于封装固定顺序的战斗结果处理。  
方法名刻意保留顺序信息，避免后续新增技能时把表现顺序写反。

| 方法 | 执行顺序 |
|---|---|
| `BroadcastThenDamage` | 先播报，再伤害 |
| `DamageThenBroadcast` | 先伤害，再播报 |
| `BroadcastThenDamageAndSetSpeed` | 先播报，再伤害，再改速度 |
| `SetSpeedThenBroadcast` | 先改速度，再播报 |
| `SetCanGetWeaponThenBroadcast` | 先设置能否拾取武器，再播报 |
| `SetCanUseBigThenBroadcast` | 先设置能否使用大招，再播报 |

示例：

```csharp
VideoGameCombatUtility.BroadcastThenDamage(
    targetRole,
    10,
    $"{RoleName}的技能命中了{targetRole.RoleName}造成了10点伤害",
    roleColor);
```

## 修改原因说明

| 修改点 | 原因 |
|---|---|
| 新增 `VideoGameCombatUtility` | 后续新增英雄/武器时，伤害、状态、播报常常一起出现，抽成薄工具可以减少重复和顺序错误。 |
| 迁移普通武器/投射物命中 | 这些位置逻辑简单，文本和数值明确，适合作为第一批战斗工具调用点。 |
| 缓存 `BaseRole` | 减少同一个碰撞对象重复 `GetComponent<BaseRole>()`，可读性和性能都更好。 |
| 保留顺序方法名 | 不同技能原本存在“先伤害再播报”和“先播报再伤害”，方法名明确顺序，降低误用风险。 |

## 风险说明

| 风险点 | 等级 | 说明 |
|---|---|---|
| 工具方法包装原调用 | 低 | 方法内部只执行原来的相邻调用，不新增判断、不改数值。 |
| `YuanShiBigKnief` 条件拆成两层 | 中低 | 原先同样是先判断 Tag，再获取 `BaseRole`，再判断目标和次数；拆分后顺序保持一致。 |
| `BanXianBaoAnRole` 缓存目标 | 中低 | 激光检测和协程流程未改，只减少同一个命中目标上的重复组件查找。 |
| `HouYiRole` / `QianBaoRole` 合并调用 | 中低 | 原顺序为播报、伤害、速度，本次工具方法保持该顺序。 |
| `Assembly-CSharp.csproj` 是生成文件 | 低 | Unity 刷新工程时可能重写该文件；真实运行脚本在 `Assets` 下。 |

## 建议人工验证点

1. 标配、奥丁命中后仍先播报再扣血。
2. 炸弹妹导弹命中后仍先播报再造成 70 点伤害。
3. 丢帽子保安、狂鼠命中后仍先扣血再播报。
4. 后羿小鸟命中后仍播报、造成 30 点伤害、眩晕 3 秒。
5. 钱包大狙命中后仍播报、造成 20 点伤害、减速 1 秒。
6. KO 圈命中后仍禁用目标大招 5 秒并播报。
7. 维斯荆棘范围内角色仍无法拾取武器 10 秒。
8. 源氏大刀仍最多攻击 3 次，并在命中后反向旋转。
9. 绊线保安命中后仍先减速并播报，再延迟造成 10 点伤害并播报。

## 使用说明

这次新增的是静态工具类，不需要挂载组件，不需要改 Inspector。  
以后新增英雄或武器时，如果只是固定顺序的战报、伤害、状态处理，可以优先使用 `VideoGameCombatUtility`。
