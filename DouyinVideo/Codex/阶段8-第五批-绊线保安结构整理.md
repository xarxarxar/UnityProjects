# 阶段 8 第五批：绊线保安结构整理

日期：2026-06-17

## 本批目标

在不改变绊线保安大招表现的前提下，整理 `BanXianBaoAnRole.cs` 的结构，让持续射线、绊线折线和设备收放流程更容易维护。

本批不做以下事情：

- 不把 `Physics2D.RaycastAll` 改成 `RaycastNonAlloc`。
- 不改变射线命中顺序和第一个命中角色的判断方式。
- 不改变发射器移动速度、射线距离、绊线延伸时间、折线跟随时间。
- 不改变减速倍率、减速时长、伤害数值、音效和战报顺序。
- 不修改 Prefab、Scene 或组件绑定。

## 代码改动说明

### 1. 清理无用引用

移除未使用的引用：

```csharp
using System.Collections.Generic;
using Unity.Burst.CompilerServices;
using Unity.VisualScripting;
```

保留实际使用的：

```csharp
using System.Collections;
using UnityEngine;
```

### 2. 提取常量

将原本散落在大招流程中的字符串和数值提取为私有常量：

| 常量 | 原值 | 用途 |
|---|---:|---|
| `WallLayerName` | `"Wall"` | 墙体射线检测层 |
| `IgnoreLayerYeLu` | `"YeLu"` | 绊线检测排除层 |
| `RoleTag` | `"Role"` | 角色命中判断 |
| `EmitterRayDistance` | `100f` | 发射器寻找墙体的射线距离 |
| `LaserRayDistance` | `100f` | 绊线向墙体法线方向延伸的射线距离 |
| `LaserWallOffset` | `0.01f` | 避免从墙面内部直接射线的偏移 |
| `EmitterMoveSpeed` | `70.0f` | 发射器飞向墙体的速度 |
| `LaserDrawDuration` | `0.1f` | 绊线延伸时间 |
| `HitFollowDuration` | `1.5f` | 命中后折线跟随角色时间 |
| `TripSpeedMultiplier` | `0.3f` | 命中后减速倍率 |
| `TripSlowDuration` | `3f` | 命中后减速持续时间 |
| `TripDamage` | `10` | 命中后最终伤害 |

这些常量只改变可读性，不改变实际数值。

### 3. 提取私有工具方法

新增私有方法：

| 方法 | 作用 | 行为变化 |
|---|---|---|
| `InitializeLaserLine` | 初始化绊线 LineRenderer | 无 |
| `FindFirstHitRole` | 保留原 `RaycastAll` 和 foreach 顺序，查找第一个命中角色 | 无 |
| `UpdateHitLaserLine` | 刷新命中后的三点折线 | 无 |
| `StartDrawLaserOverTime` | 停止旧检测协程并启动新绊线协程 | 无 |
| `ActivateLaserDevices` | 显示发射器和接收器 | 无 |
| `DetachLaserDevices` | 让发射器和接收器脱离角色父物体 | 无 |
| `CloseLaserDevices` | 关闭绊线并把设备挂回角色 | 无 |
| `StopBigCoroutine` | 停止发射器移动协程 | 无 |
| `StopDrawLaserOverTimeCoroutine` | 停止绊线延伸和检测协程 | 无 |

### 4. 保留持续射线分配

`DrawLaserOverTime()` 里仍然每帧调用：

```csharp
Physics2D.RaycastAll(...)
```

本批没有改成 `RaycastNonAlloc`。原因是当前逻辑依赖 `RaycastAll` 返回结果的遍历顺序来决定“第一个被绊线命中的角色”，如果改成 NonAlloc，需要额外验证排序和缓冲区容量，否则会有玩法风险。

### 5. 保留调试日志

原逻辑命中角色时会执行：

```csharp
Debug.Log($"击中了{hitRole.name}");
```

本批保留该日志。它不是高频每帧刷屏日志，只在绊线找到命中角色时输出一次；直接删除可能影响你调试绊线命中。

## 行为保持点

| 行为 | 保持方式 |
|---|---|
| 大招入口 | `Big()` 仍只调用 `ShootLaserEmitter()` |
| 目标方向 | 仍使用 `otherBaseRole.transform.position - transform.position` |
| 发射器命中墙体 | 仍用 `Wall` 层、距离 `100` 的 `Physics2D.Raycast` |
| 发射器设备显示 | 仍先显示发射器和接收器，再脱离父物体 |
| 发射器移动 | 仍按 `70.0f` 速度移动到墙体命中点 |
| 绊线方向 | 仍使用墙体命中法线 `hit.normal` |
| 绊线延伸 | 仍用 `0.1f` 从起点延伸到终点 |
| 持续检测 | 仍每帧 `RaycastAll`，排除 `YeLu` 层 |
| 命中角色 | 仍排除自己，取第一个 Tag 为 `Role` 的对象 |
| 命中效果 | 仍先减速播报，再播放音效，再折线跟随，最后伤害播报 |
| 折线跟随 | 仍持续 `1.5f`，每帧刷新三点线 |
| 结束收尾 | 仍关闭 LineRenderer、挂回发射器和接收器、再隐藏设备 |

## 风险说明

风险等级：中低。

原因：

- 修改了复杂英雄的大招脚本结构。
- 没有改变数值、射线类型、命中筛选、协程启动顺序和设备绑定。
- 主要风险来自方法提取过程中是否遗漏原有设备收放顺序。

本批没有修复 `otherBaseRole` 为空时可能空引用的问题，因为这会把“异常”改成“静默不释放大招”，属于行为变化，需要后续单独确认。

## 建议验证点

1. 绊线保安释放大招后，发射器和接收器仍一起飞向墙体。
2. 发射器命中墙体后，绊线仍沿墙体法线方向生成。
3. 绊线仍会在约 `0.1f` 内延伸完成。
4. 角色经过绊线时，仍输出原命中日志。
5. 命中后绊线颜色仍变为命中颜色。
6. 命中后仍先减速并播报，再播放音效。
7. 绊线折线仍跟随命中角色约 `1.5f`。
8. 折线结束后仍造成 `10` 点伤害并播报。
9. 命中结束后发射器和接收器仍隐藏并挂回角色。
10. 连续释放大招时旧移动协程和旧检测协程不会残留。
