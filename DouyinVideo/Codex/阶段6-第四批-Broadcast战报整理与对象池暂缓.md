# 阶段 6 第四批：Broadcast 战报整理与对象池暂缓

日期：2026-06-16  
目标：审查战报 UI 的性能优化空间，并在不改变战报显示规则的前提下做低风险代码整理。  
主场景：`Assets/Scenes/VideoScene.unity`

## 本批结论

本批没有实现战报对象池。

原因：

- 当前 `Broadcast` 每条战报都会实例化一个新的 `Text`，并一直保留在滚动列表中。
- 如果要真正池化战报文本，必须让旧战报进入回收流程。
- 一旦回收旧战报，就需要引入“最多保留多少条”“何时隐藏旧记录”“滚动条历史如何变化”等规则。
- 这些规则会改变当前战报历史完整保留的表现，不符合阶段 6 的安全约束。

因此本批只做无行为变化整理：

- 清理无用 `using`。
- 删除未使用字段和未使用计数。
- 拆分创建战报文本和刷新滚动位置两个私有方法。
- 为公开入口和重要私有方法补充中文 XML 注释。

没有改动：

- 没有修改 `BroadCastNews` 的公开调用方式。
- 没有修改 `Text` 预制体绑定。
- 没有修改 `textParent`、`scrollRect` 绑定。
- 没有修改战报文本内容、颜色或创建顺序。
- 没有移除 `Canvas.ForceUpdateCanvases()`。
- 没有修改 `scrollRect.verticalNormalizedPosition = 0f`。
- 没有增加战报数量上限。

## 当前战报流程

`BroadCastNews(news, color)` 的执行顺序保持为：

1. 实例化 `broadText` 到 `textParent`。
2. 设置 `tmp.text = news`。
3. 设置 `tmp.color = color`。
4. 调用 `Canvas.ForceUpdateCanvases()`。
5. 设置 `scrollRect.verticalNormalizedPosition = 0f`。

本批只是把这些步骤拆成：

- `CreateNewsText(news, color)`
- `RefreshScrollToBottom()`

执行顺序没有改变。

## 暂缓对象池的原因

战报文本和音效对象不一样：

- 音效播放结束后天然可以回收。
- 战报文本没有“播放结束”这类生命周期。
- 当前表现是所有战报持续留在列表里。
- 如果池化，需要删除或隐藏旧战报，这会改变可见历史记录。

所以战报对象池需要先确认设计规则：

| 需要确认的问题 | 影响 |
|---|---|
| 最多保留多少条战报 | 会改变滚动列表历史长度 |
| 超出上限时删最早还是隐藏最早 | 会影响回看历史 |
| 是否允许长时间录制后只保留最近记录 | 会改变录制 UI 表现 |
| 是否需要导出完整日志到文件 | 可补偿 UI 不再保留全部历史的问题 |

在这些规则确认前，不建议直接池化。

## 风险说明

本批风险为低。

原因：
